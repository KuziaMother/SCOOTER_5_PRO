## BLE-часть — RTL8762C (`ble_2.7.0_0015.bin`, база флеша 0x01800000)

### Регионы образа

| Регион | Размер | Статус | Примечание |
|---|---|---|---|
| OTA-заголовок `0x0` | 1 КБ | ✅ | GUID, адреса загрузки, `&release#`, `ic_type=5, xip=1, enc=1, enc_key_select=7` (§5, §6.11, §30.5) |
| Bootloader / DFU `0x400–0x3000` | ~9,7 КБ | ✅ | PLAIN-код, все функции в справочнике: CTR-заголовок, приём DFU-пакетов, BP-unlock, dual-bank, erase (§2) |
| SPI-flash драйвер + OTA `0x6000–0xa200` | ~16,9 КБ | ✅ | PLAIN-код, разобран: RDID, стирание секторов, BP-управление (§2) |
| **APP `0xa200–0x25400`** | ~111 КБ | 🚧 **AES** | энтропия 7.98–8.0, не ECB, S-box'ов в образе нет → аппаратный XIP-декрипт, ключ per-chip из eFuse (§3, §6.2, §19.2). Программная декомпиляция из .bin — **невозможна** |
| Trailer (TFOTA) `0x25400` | ~1,3 КБ | ✅ | цепочка сертификатов Mijia (ECDSA P-256), подпись; подписываемое сообщение не восстановлено (§4, §30.1–30.3, §30.7) |

### Поведение чипа на уровне протокола (не декомпиляция, но установлено)

| Что | Статус | Раздел |
|---|---|---|
| MiBeacon в рекламе — только идентификация | ✅ | §6.12.4 |
| Подписка пуша = CCCD на `0x001b`; 20 подписываемых свойств | ✅ (механизм; live-пуш не пойман) | §18 |
| Процедура bind — живой снуп, последовательность записана | ✅ | §21 |
| Чтение телеметрии: бинарный формат spec-кадра + шифрование `BleSecurityChipEncrypt` отреверсены, проверено на живом устройстве | ✅ | §6.13, §6.14 |
| SET-протокол из dex («стена последней мили» закрыта); `0x0005` = характеристика привязки | ✅ | §20.4–20.5 |
| Карта всей телеметрии (siid/piid) из плагина Mi Home | ✅ | §6.13.3, §14 |
| Соответствие siid/piid ↔ USART3 CMD 0x41..0x4B | ⬜ | §35.3 — живой снуп |

### Почему APP-регион не декомпилируется (финальный вердикт)

1. `xip=1 + enc=1` → inline-декрипт на шине при исполнении; ключ = OCEK из eFuse,
   per-chip (комбинация с UUID чипа на заводе, формула не документирована) — §6.11, §19.2.
2. UART-дамп (`rtltool read_flash`) даёт **шифртекст** — не обходит шифрование — §6.11.
3. eFuse Read на security Level 2 (рекомендация Realtek для mass production) — **Disable
   без разблокировки**; SWD, вероятно, за паролем — §19.2.
4. Рабочие методы только аппаратные: **SWD-дамп XIP-региона `0x0180E000`** на живом чипе
   (если SWD не залочен) или **захват FOTA-пакета** из Mi Home — §30.6.

### Стены MCU (почему дальше из файла не уйти)

- Вектор-таблицы/точки входа в OTA-образе нет → широкая эмуляция от init невозможна — §16.3.
- Многие задачи вызываются по RAM-указателям (data-driven, §26.2) → статически не находятся
  писатели отдельных полей (u16@0x32e/0x330 — CPU-писателя в образе нет, §26.4).
- Рантайм-значения (таблица команд @0x20000A43, blob-конфиги, счётчики) — только живой снуп / SWD-RAM.
